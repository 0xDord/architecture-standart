### <a name="_qmphm5d6rvi3"></a>**Решение**

**Логика выбора решений:**
- Использовать существующие технологии и экспертизу банка
- Разгрузить ядро системы, вынести функционал по отправке СМС в отдельный микросервис, также появится возможность новых доработок этого функционала
- В новых микросервисах использовать асинхронное общение через kafka, с перспективой event driven подхода в дальнейшем
- Для MVP — заявки обрабатываются вручную бэк-офисом, автоматизация на следующем этапе
- Для интеграции использовать промежуточные сервисы/шины, чтобы не перегружать АБС и обеспечить масштабируемость
- Обеспечить шифрование данных на всех этапах передачи

### <a name="_bjrr7veeh80c"></a>**Альтернативы**
- Прямая интеграция интернет-банка с АБС (отказались из-за рисков перегрузки и низкой масштабируемости)
- Автоматизация обработки заявок на первом этапе (отложено до финального этапа, чтобы быстрее запустить MVP)
- Оставить функционал отправки СМС в ядре системы (отказались, чтобы не зависеть в разработке от подрядчика)
- Хранить ставки в АБС(отказались из-за долгого отклика, быстрее взять из кэша нового микросервиса)
- Синхронное взаимодействие между сервисом депозитов и уведомлений(отказались в пользу асинхронного решения с масштабированием)

**Недостатки, ограничения, риски**
- Перегрузка АБС при большом количестве онлайн-заявок
- Необходимость ручной обработки заявок на этапе MVP (ограниченная автоматизация)
- Ограниченная масштабируемость АБС (только вертикальная)
