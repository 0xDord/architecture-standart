### <a name="_bjrr7veeh80c"></a>**Альтернативы**
- Прямая интеграция АБС с системами кол-центров (отказались из-за сложности доработки системы, не соответствующего тех.стека и низкой масштабируемости АБС)
- Прямая интеграция deposit-service с системами кол-центров (отказались из-за сложности доработки системы, не соответствующего тех.стека и низкой масштабируемости АБС)
- Отправка сообщений во внутренний кол-центр по kafka (отказались, так как нагрузка в процессе заведения/изменения ставок достаточна для реализации через REST)
- Отправка файла в формате xml (отказались, потому что структура данных не иерархичная, удобнее работать с csv)
- Лонгполлинг select запросами систему АБС для получения изменений по ставкам (отказались, чтобы не перегружать АБС)

**Недостатки, ограничения, риски**
- Необходимость в дополнительных сценариях взаимодействия, в случае, если ставку необходимо изменить или удалить
- Новые поля и любое изменение формата файла со ставками нужно согласовывать с командой партнерской системы
- Неудобство во взаимодействии по sftp, нужно предусмотреть дополнительные проверки, что файл был обработан сторонней системой
- Плохое масштабирование sftp взаимодействия
